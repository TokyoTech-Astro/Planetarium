# 配線・導入

## 統括・モーター基板（XIAO ESP32C3）

`motor_driver_回路図.pdf` に合わせています。

| XIAO端子 | 信号 | 用途 |
|---|---|---|
| D0 | MO | SLA7078モニター入力 |
| D1 | M2 | 励磁モード設定 |
| D2 | CLOCK | ステップパルス |
| D3 | CW/CCW | 回転方向 |
| D4 | FLAG | ドライバー異常入力 |
| D5 | SYNC | 同期設定 |
| D6 | RESET | ドライバーリセット |
| D7 | M3 | 励磁モード設定 |
| D8 | M1 | 励磁モード設定 |
| D9 | ref/sleep_mcu | Sleep1制御（LOWでスリープ、通常動作はHIGH） |
| D10 | led_status | 状態LED |

`firmware/coordinator/platformio.ini` の設定値:

- `MOTOR_FULL_STEPS_PER_REV`: モーター単体のフルステップ/回転
- `MOTOR_OUTPUT_CALIBRATION`: 実機の出力角補正倍率。現行実機は3.0。
- `MOTOR_MICROSTEPS`: SLA7078で設定した分割数
- `MOTOR_DIRECTION_INVERT`: 回転が逆なら1
- `MOTOR_MAX_OUTPUT_SPEED_DEG_SEC`: 出力軸の最高速度（度/秒）

使用モーターは **PK296A10SG36（1.5 A/相、2.2 Ω/相）** を前提としています。公称値は出力軸1回転7,200パルスですが、実機が指令角の約1/3だけ動く現象への補正として3.0倍を適用し、制御上は21,600パルス/回転（60パルス/°）としています。この倍率は目標角度、速度、相対移動、現在角度推定のすべてに共通です。

相電流1.5 Aの設定はソフトウェアではなく、SLA7078基板のVREF/電流設定回路で実機調整してください。

### 角度コマンド

- 通常値: 0°以上360°未満で管理します。360°は0°、720°も0°として扱います。
- 現在位置から同じ角度になる最も近い方向へ移動するため、連続回転後に何周も巻き戻しません。
- `999`: 指定速度で時計回りに連続回転します。
- `-999`: 指定速度で反時計回りに連続回転します。±999は物理角度ではなく専用コマンドです。
- 連続回転の停止: 速度を0°/sにするか、±999以外の目標角度を送ります。

### 再起動時の安全動作

- 再起動すると原点は未設定になります。
- 原点未設定中は通常角度指令と±999連続回転指令を拒否します。
- 校正画面のジョグ、相対移動、停止は原点合わせのため使用できます。
- 校正画面を開いた時点で直ちにSTOPを送り、速度入力の初期値は0°/sになります。
- 「現在位置を0°に設定」または「角度設定」を実行すると通常制御を解禁します。
- ライトは起動時に全OFFとなり、PC再接続後はモーターがロック中でもライト設定だけ復元します。
- UIと通信上の角度は0°以上360°未満で管理します。内部ステップ数だけは正確なパルス管理のため累積保持します。

## ライト基板

`seiza_ittose_回路図.pdf` に合わせています。

| 機能 | XIAO端子 |
|---|---|
| 恒星 | D0 |
| 一等星 | D1 |
| 未接続 | D7 |
| ペガスス座 | D8 |
| いて座 | D9 |
| さそり座 | D10 |
| 未接続 | D5 |
| こいぬ座 | D4 |
| おおいぬ座 | D3 |
| オリオン座 | D2 |

恒星出力D0だけは回路上アクティブLOWです。論理ONでGPIO LOW、論理OFFでGPIO HIGHを出力します。一等星と接続済み星座出力はアクティブHIGHです。UIと指示送信TXTには物理レベルではなく、通常どおり論理的なON/OFFを記述します。未接続のD7とD5はUI側で常時OFFに固定します。

## 構成

PCは統括・モーター基板へUSB/UART接続します。統括・モーター基板からライト基板へESP-NOWで指令を送り、ライト基板が反映状態を返信します。

統括・モーター基板のPC通信はXIAO ESP32C3のUSB CDCを使用します。USB通信はUSB-C端子内部のD+/D-を使用するため、外周端子D6（UART TX兼用）とD7（UART RX兼用）は通常GPIOとしてモーター回路に使用できます。

ESP32C3はシングルコアです。通信処理はFreeRTOSタスクで実行し、モーターのCLOCKパルス生成はハードウェアタイマー割り込みへ分離しています。したがって、ESP-NOWやJSON処理が動作している間もタイマー割り込みがステップ生成を継続します。
